## Environment & honesty notes
- Everything ran on 127.0.0.1 only, inside headless Firefox, with a browser-level network fence that aborts every request not addressed at 127.0.0.1 or the allowed CDNs. No external service was contacted, no real users exist (the product has none), nothing was hammered (≤5 req/s).
- This product has **no backend, no database, no accounts** (verified by asset scans + runtime DOM inventories; see AUD-01/03/04, OUT-02/04/05 rows). The five "impersonate/limits" attacks that target auth/API surface are therefore proven N/A with runtime evidence, and adjacent client-side equivalents were tested against the actual surfaces.
- Fixes verified per the requested discipline: run attacks on the untouched tree (attack succeeds → `before`), apply fix, rerun the same scripts (attack refused → `after`), plus spot "protections off/on" cycles by using the pristine checkout as the "off" state.
- **Evidence provenance (2026-10-18 / post-push hardening):** the full `tests/results/` tree (before + after, report.md + report.json + artifacts) is committed to the repository, because an out-of-session process overwrote parts of the on-disk `before/b` bucket that day. `before/b` was honestly REGENERATED against the pristine pre-fix checkout (`c4f911e`) using the same runner — the pre-fix site code is byte-identical, so those rows carry the identical runtime guarantee as the original generation (a dated note inside `tests/results/before/b/report.md` says so). `before/a` was restored byte-identically by the agent that had produced it (appendix documents the restoration). The runners additionally gained incremental row-resume ("[skip] already recorded") and pre-fix collector-log parsing so later regenerations can't lose one-phase facts; and the recorder can no longer write the `before/` bucket without an explicit `RESULTS_PHASE=before` (bare runs land in regenerable `after/` by default).

## Headline finding — share-link code execution w/ library theft (OUT-01)

**Before:** `editor.html#code=<base64 JSON>` links executed attacker JSON-decoded code inside the app page (`new Function`) at the **app origin**, auto-run at load. A victim library seeded with `secret-thing.jsx` was exfiltrated by one opened link — collector request, verbatim:

```
GET /leak?lib=%5B%22jsxpress%3A__draft%22%2C%22jsxpress%3Af_secret%22%2C%22jsxpress%3Alayout%22%2C%22%7B%5C%22name%5C%22%3A%5C%22secret-thing.jsx%5C%22%2C%5C%22code%5C%22%3A%5C%22%2F%2FA-private-code-SECRET123%22...
```
(stolen keys list: draft + the secret file + layout — all victim data).

**After:** the same payload runs inside `<iframe sandbox="allow-scripts">` with no `allow-same-origin`: `window.top.localStorage` access throws `SecurityError` and **0 leak requests** reach the collector; the parent's library is untouched. Identical scripts, identical vectors — only the tree changed.

## Additional hardening committed in this pass
- `index.html`, `editor.html`: strict CSP metas (no `unsafe-inline`/`unsafe-eval` script sources; `connect-src 'self'`; `object-src 'none'`).
- `assets/editor.js`: sandboxed run pipeline with per-run nonce handshake; removed dead `reactRoot`; quote/backtick-safe `escapeHtml`; 4096-char cap on `#code=` payloads.
- `sandbox-wrap.html` (new): sandbox execution environment, SRI'd React/ReactDOM, Tailwind scoped inside, error/no-component bridge over postMessage.
- `assets/editor-boot.js` (new): the only head-time script, externalized so CSP stays strict.
- `assets/home.js`: template fields escaped before interpolation.
- `assets/editor.css`: preview sandbox iframe layout.
- README: model documented (Security model; Limitations update).

## Known residuals (documented, deliberately not "fixed")
- `cdn.tailwindcss.com` serves a dynamic bundle and cannot carry SRI; the app CSP allowlists the host and the sandbox frames it.
- GitHub Pages can't set `frame-ancestors` (meta CSP ignores it); framebusting is deliberate-lazy here since the editor is meant to embed cleanly when self-hosted.
- The parent's ping-verification of the sandbox is a defense-in-depth for engines that allow sandbox self-navigation; Firefox already blocks it at the sandbox level.
- Vendoring the CDN libraries into the repo would remove the supply-chain surface entirely (follow-up candidate).
